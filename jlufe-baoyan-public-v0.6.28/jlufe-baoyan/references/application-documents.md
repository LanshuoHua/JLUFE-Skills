# 推免文书模板与核对

先确认文书用途和目标项目，再选择一份模板。夏令营、预推免和正式接收分别核对接收院系的当批通知。公告给出固定表格、语言、字数、时长、匿名要求、提交方式或签章要求时，按该批次执行。模板里的 `【字段】` 供替换，缺依据的项目留待确认或从提交稿删除。

润色时先保留原稿中有依据的事实和个人表达。若目标尚未确定，先交付可继续修改的通用稿，把院系要求与项目匹配段留待核对。只询问当前这份文书需要的信息。

| 要准备的文书 | 模板 | 填写重点 |
|---|---|---|
| 简历 | [中英文简历](../assets/application-templates/resume.md) | 排名口径、项目角色、成果状态和目标匹配 |
| 个人陈述 | [个人陈述](../assets/application-templates/personal-statement.md) | 申请动机、代表经历、选择该项目的依据 |
| 专家或教师推荐材料 | [推荐信草稿](../assets/application-templates/recommendation-letter.md) | 推荐人直接观察到的事实、审阅与签署 |
| 面试开场 | [中英文自我介绍](../assets/application-templates/self-introduction.md) | 按实际时长组织一段能展开追问的经历 |
| 研究或学习计划 | [研究计划](../assets/application-templates/research-plan.md) | 可回答的问题、数据可得性、对照验证和阶段产出 |
| 联系目标导师 | [导师联系邮件](../assets/application-templates/supervisor-email.md) | 具体匹配依据、准确资格状态和一个明确请求 |
| 面试展示 | [面试汇报提纲](../assets/application-templates/interview-deck.md) | 按页组织个人工作与证据，按场次要求计时 |

## 把经历核对后再写进文书

1. 确认目标院校、校区、院系、项目名称、专业代码、学位类型和批次。同步记录用户实际要交的格式和用途。学校官方证明、诚信承诺书或指定推荐表，使用当届官方原表。 [申请流程](application-workflow.md) · [历年校院通知与附件](jlufe-notice-index.md)
2. 按文书用途取最少的可核字段。排名按现有证明写名次、总人数、排名范围和统计学期。GPA 写清满分，加权均分写清课程范围。外语注明考试类型、成绩或等级和出分时间。将本人自述与已核证明分开记录，缺证或口径未明的数字列入待确认项。校内推荐资格使用实际状态，排名证明单列。需要查校内资格或证明办理时，先按 [Skill 入口](../SKILL.md) 确认学籍归属。
3. 对一至两个代表经历记录题目、时间、数据、方法、个人贡献、团队产出、结果和局限。竞赛写正式赛名、奖级、赛道及团队或个人。论文写作者位置与实际状态，区分在研、投稿、录用、网络首发及见刊。使用有来源的量化结果，给出样本和对照口径。 [个人信息与成果记录模板](../assets/profile-and-evidence.md)
4. 先生成可编辑正文，再列出少量待本人核对的字段。按目标用途调整篇幅。个人陈述解释动机，简历提供证据线索，面试稿让对方听得懂，研究计划呈现尚需验证的工作。个人提交稿按实际要求填写身份和联系方式。匿名考核稿按通知处理姓名、考号、学校、专业和其他可能识别个人的信息。

## 提交前检查

- 对照目标通知核对院校、院系、项目名、称谓、批次及附件顺序。跨投时逐份检查抬头、导师、方向和其他学校的残留内容。
- 对照同一份证据核对简历、陈述、邮件和汇报里的排名、外语、时间、作者顺序、获奖级别和个人贡献。仍处于申请、预报名或拟推荐阶段时按实际状态写。
- 推荐信、资格证明、签名和印章由真实主体办理。需要推荐人通过专用链接或学校邮箱提交时，由本人按当批规则操作。起草导师邮件时提供可审阅草稿。
- 公开模板使用空白占位。公开整理经验时，核对去名后的学校、成绩、作品名称及奖项组合是否仍能识别个人。附件只选有权提供且与申请相关的材料，检查照片、签章、二维码、表格截图、批注、修订记录、文档属性、外链和演讲者备注。复用结构时重新起草，正文与附件分开核对。

## 模板来源与维护

模板从用户提供的简历、陈述、推荐、面试口述、研究计划、导师邮件和面试展示样例中归并共用结构，再按申请场景重新写成 Markdown。更新时沿用七类入口，将个人和第三方的识别字段替换为占位，保留能影响填报或核验的结构性信息。
